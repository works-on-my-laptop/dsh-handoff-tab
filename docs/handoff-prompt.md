# 会话交接提示词（通用版 · v3 单一提示词）

- 日期：2026-11-12
- 用途：会话结束前运行一次，产出一份**可以直接粘贴到下一个会话的第一条消息**。全文都是提示词，没有文档外壳。
- 适用：编码、调研、写作、运维等任何"人会中途换会话继续"的工作。
- 不适用：单轮问答、无后续工作的纯查询。

> **代码同步**：本文件的「提示词正文」与 `index.js` 里的 `SYSTEM_PROMPT` 必须逐字一致（`npm test` 中的 `test/prompt-sync.cjs` 会校验）。修改任一处时必须同步另一处，并把 `index.js` 的 `PROMPT_VERSION` 加 1。

## 怎么用

1. 在当前会话末尾，把下面「提示词正文」**整段**作为一条新消息发出（无需填参数）。
2. 它返回一段文本——新会话的第一条消息就是它，不需要再改写或摘取。新会话读完会先复述理解到的任务/进度/下一步，问你「接下来做什么」，得到确认后才开工。
3. DSH 插件 `dsh-handoff-tab` 里，这段文本就是「交接」tab 的正文；点复制拿到的也是它。

## 提示词正文

```text
# 角色
你熟悉当前会话的全部内容（对话、产出的文件、执行过的命令与结果、做过的决策）。但你要写的东西不是给人看的报告，而是**给一个完全没有本会话记忆的新 agent 的开场提示词**。

# 任务
写一段可以直接粘贴到新会话的第一条消息。**全文都是提示词**：从第一个字开始就是对下一位 agent 说的话，到最后一个字为止。

不要出现：文档标题、「交接说明/交接文档」之类自称、引言、结语、「以下是……」、生成时间、会话 ID、完成度百分比、以及任何面向人的说明。正文之外不要再输出任何内容。

# 正文必须让接手者知道
1. 在做什么：项目/任务的背景、最终要达成什么、验收标准。
2. 做到哪了：已完成、进行中、未开始、已废弃各是哪些；能给出证据的写路径、命令、结果。
3. 定了什么：关键决策与理由，**以及被否决的方案和否决原因**（防止重做）。
4. 东西在哪：文件与目录路径（相对工作区根目录）、用途、当前状态。
5. 有什么坑：试过但失败的做法、容易误解的点、已排除的假设。
6. 接下来做什么：按优先级，每条写清"做什么 + 改哪里 + 验收标准"。
7. 什么不能动：用户明确提的要求、不可更改的前提、目录与命名规范、环境依赖、禁止事项。
8. 先确认再动手：正文必须要求接手者读完先不要执行任何操作，先用自己的话向用户复述理解到的「在做什么、现在到哪、建议的下一步」，再问用户接下来做什么，得到确认后才开始。

# 写法
- 用第二人称"你"称呼接手者，祈使句为主（"先读 X""不要动 Y""改成 Z 再验证"）。
- 用短段落、列表、加粗强调来组织，不要用文档式的大标题层级。
- 具体到路径、命令、参数、字段名。禁止"那个文件""之前说的方案""如上所述"这类依赖旧对话的指代——新会话看不到旧对话。
- 涉及文件、目录与产物时，以输入里的「CURRENT WORKSPACE SNAPSHOT」为准；快照里没有列出的文件或构建产物不要声称存在，拿不准就写成行动（"先核实…"）。
- 事实给证据，判断给理由；推断标「推断」，未验证标「未验证」。
- 不确定的地方写成行动（"先核实 X，再决定 Y"），不要写成结论，更不要编造。
- 800–2000 字，宁详勿简：每句话要么是事实，要么是行动指令。
- 跟随会话使用的语言。
- 「先复述、再确认」这条要求必须出现在正文开头（前几行），不要埋到结尾——否则接手者会拿着信息直接开工。

# 自检
把这段文本单独作为新会话的第一条消息发出去，检查三件事：
1. 新 agent 能否立刻知道"做什么、从哪开始、什么不能碰"？不能就补。
2. 它读完会不会先复述理解、再问用户接下来做什么，而不是直接开工？不会就补上这条要求。
3. 它会不会反问"你要我做什么"？会就说明开头没把任务写出来。

# 开始
动笔前先在上下文里核对信息；信息不全就按"先核实"的写法处理，不要为了凑结构而编造。
```

## 按需微调（在正文末尾追加一句即可）

| 场景 | 追加内容 |
| --- | --- |
| 想要更短 | `正文压到 500 字以内，只保留任务、当前状态、下一步。` |
| 偏代码交接 | `把改动点细化到文件和函数，未提交内容单独说明。` |
| 偏调研交接 | `补充已查证来源与仍待核实的说法，并标出证据强度。` |
| 面向真人接手 | `把"你"从 agent 换成新同事，保留同样的信息。` |
| 想更严格 | `全文禁止任何指代旧对话的表述，全部替换成具体名词与路径。` |

## 这些约束在防什么

| 约束 | 防的失败模式 |
| --- | --- |
| 全文即提示词、无文档壳 | 产出一份报告后还要人工拆出可粘贴的部分；新会话读到元信息而分心 |
| 禁止指代旧对话 | 新会话读不懂"那个方案"，接手即卡住 |
| 未验证/推断必须标注 | 把猜测写成事实，下一会话在错误前提上继续做 |
| 必须写证据 | "已完成"无凭据，实际没跑通 |
| 必须写被否决方案 | 新会话把已否决的思路重做一遍 |
| 下一步含验收标准 | "继续完善"这类空话无法执行、无法判断结束 |
| 先复述理解、确认后再开工 | 接手 agent 拿着交接信息直接大改，方向错了才发现 |
| 800–2000 字 | 太短丢关键信息，太长短到没人读完 |
